## Topic: Project goal and positioning
- source: docs/DESIGN.md section 1
- notes: ORB-SLAM3-inspired visual SLAM library (mono + stereo), C++20, Eigen, Conan 2, with a different concurrency model: no locks on the map; threads communicate only through publish/subscribe events over lock-free queues and each keeps its own replica. Predecessor project `../slamlab2` (image processing, feature extraction, geometry, distortion models were ported from it). Long-term goal beyond ORB-SLAM3: mixed mono and binocular keyframes in one map (Open Question 17). Consumed from desktop and from an Android app (Kotlin + JNI) through the Conan package. Reference dataset TUM-VI `dataset-corridor1_1024_16`; a mocap room at the start and end of corridor1 makes end-of-run ATE measure loop-closing quality.

## Topic: Stereo-drift spike (root cause of the BoW-era stereo regression)
- source: .superpowers/spikes/2026-10-07-stereo-drift.md (2026-10-07, base master 6591fb6, throwaway worktree)
- notes: The regression was not gradual drift; damage occurred in fast-rotation stretches (corridor1 frames 324-325, 354-356, 366-368, 376-378). Trigger: the Tracker accepted a motion-model pose with only 10-29 inliers; `need_close` then turned that frame into a Frame whose roughly 320 stereo close points carried the wrong pose; with BoW the Mapper published that Frame about 15-25 ms later, before the next frame, so the Tracker locked onto the misplaced points. Fix recorded in DESIGN (2026-10-08): `min_motion_model_inliers` = 30, with zero-motion (minimum 10) as fallback. Result: stereo 1000 with vocabulary 0.0361 / 0.0363 / 0.0369 m, one map; mono unchanged (gate never fires). Machine was slower than the DESIGN smoke (extraction 160-180 ms per stereo frame, local BA 120-190 ms); sequential runs only, because concurrent runs inflate local BA timing.
