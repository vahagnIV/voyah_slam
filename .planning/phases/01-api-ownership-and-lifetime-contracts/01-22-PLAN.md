Exception type choice (planner's decision under DESIGN §7, documented in Task 3): `voyahslam::UsageError` stays for invalid call *sequences* (a later call can succeed: Start twice, connect while running, Stop on the own worker). Invalid argument *values*, which can never succeed, throw the standard `std::logic_error` subclasses that already say so, following the 0.9.0 precedent of `std::length_error` for an overflowing `Image` size: `std::out_of_range` for a view rectangle outside its parent, `std::invalid_argument` for a `CopyTo` target of another size, an image too small for the ORB pyramid and an invalid extractor configuration. All of them derive from `std::logic_error`, so a binding can still catch that once; voyah_jni maps them to `IndexOutOfBoundsException` / `IllegalArgumentException` instead of `IllegalStateException`.
