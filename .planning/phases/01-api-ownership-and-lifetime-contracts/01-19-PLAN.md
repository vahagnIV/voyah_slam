Current code (`libs/common/include/voyahslam/images/image.h`, 155 lines): `Image() = default` leaves `offset_`, `width_`, `height_`, `stride_` uninitialised; the size constructor allocates `new T[width * height * C]` in unsigned arithmetic; `Set(...) const`; `Convert()` loops `width_ * height_` (no channels, no offset/stride); `operator*=` / `operator*` loop over the flat buffer; the move constructor and move assignment leave the source's sizes set; `CopyTo`'s strided branch copies `width_ * C` bytes (missing `sizeof(T)`) and `<cstring>` is not included; `operator[]` returns a row view, then on a single-row view a pixel view (`offset_ + i * C`), then on a 1x1 view a channel (`offset_ + i`). No caller uses `Convert`, `operator*` or `operator[]` outside the header; `Set` is called on non-const locals in `libs/algs/include/voyahslam/images/filter.h` and `gaussian_blur.h`. `01-RESEARCH.md` "Pattern 9" and Pitfall 16. Research listed the 1x1 `operator[]` offset as a defect; reading the chain, `img[y][x][c]` selects channel `c`, so the offset is correct: this plan pins it with a test and documents it instead of changing it (planner's resolution of Pitfall 16c). The shape-dependent meaning of `operator[]` on a single-row image (row versus pixel) has no caller; it is recorded in TODO, not changed.
