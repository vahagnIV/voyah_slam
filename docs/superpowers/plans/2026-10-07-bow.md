# Bag of Words without OpenCV Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** An OpenCV-free DBoW2 port (`voyahslam::bow`) that loads ORB-SLAM3's `ORBvoc.txt` (and our binary format), gives every Mapper Frame its BoW data, and replaces brute-force triangulation matching with `SearchByBoW`.

**Architecture:**
- **`voyah_algs` gains `bow/`:** `Vocabulary<FE>` (flat arrays), `BowVector`, `FeatureVector`, `Transform`, `Score`, the text and binary loaders, and a converter tool.
- **Mapper wiring:** the app owns an immutable `shared_ptr<const Vocabulary>` and passes it through `Slam` to the Mapper. `SearchForTriangulation` takes optional FeatureVectors.
- **Equivalence check:** against the original DBoW2, through a committed fixture.

**Tech Stack:** C++20, Eigen, GoogleTest, CMake/Conan. Original DBoW2 and OpenCV are used only in a scratch reference build, outside the repo.

**Spec:** `docs/superpowers/specs/2026-10-07-bow-design.md`

## Global Constraints

- **Branch:** `feat/bow`. Commit per task. Never merge or push.
- **Naming:** Google style. `PascalCase` types and functions, `snake_case` variables, `snake_case_` members, `out_` prefix for non-const reference parameters.
- **Layers:** `bow/` is in `voyah_algs`, namespace `voyahslam::bow`. No OpenCV in `voyah_algs` public headers. No upper-layer includes.
- **Vocabulary:**
  - immutable after load and shared via `std::shared_ptr<const bow::Vocabulary<FE>>`;
  - may be null, and with null the behaviour is exactly as today;
  - the vocabulary file is never committed.
- **Algorithm:** DBoW2 TF-IDF weighting and L1 scoring.
  - Child ties go to the first child in stored order.
  - The FeatureVector `levels_up` is 4 in the Mapper.
- **Build and test:**
  - Debug tree: `cmake-build-debug/build/Debug`.
  - Fast loop: `--target check`. End of each task: `--target check_all`, plus building the apps and Release (`build/build/Release`).
  - cmake binary: `/home/vahagn/Programs/clion/clion-2025.1.3/bin/cmake/linux/x64/bin/cmake`.
  - Current total: 504 tests.
- **Header check:** clang-18 with libc++ `-fsyntax-only` on new or changed public headers, using only their library's and lower libraries' roots.
- **Docs:** `docs/DESIGN.md`, `docs/TODO.md`, `docs/ROADMAP.md` and `README.md` change only in Task 7.

## Review Focus

1. **An empty descriptor set,** for example a Frame with zero features.
   - Expected: `Transform` returns an empty BowVector and FeatureVector; `Score` with an empty vector is 0.
   - Test: Task 1, `VocabularyTest.EmptyDescriptorsGiveEmptyVectors`.
2. **A vocabulary whose descriptor size doesn't match the extractor,** for example a 32-byte ORB vocabulary for `Mapper<SIFTFeatureExtractor>`.
   - Expected: the loaders return `nullopt` with a logged reason; a Mapper without a vocabulary works.
   - Test: Task 2, `VocabularyIoTest.RejectsDescriptorSizeMismatch`.
3. **A malformed text vocabulary:** non-numeric tokens, a missing weight, a truncated last line.
   - Expected: `nullopt` and no crash.
   - Test: Task 2, `VocabularyIoTest.RejectsMalformedText`.
4. **A structurally broken tree:** a parent id ≥ the node's own id, an inner node with no children, or a leaf with children.
   - Expected: rejected at load, binary or text.
   - Test: Task 2, `VocabularyIoTest.RejectsBrokenTree`.
5. **`levels_up` ≥ the tree depth.**
   - Expected: features are filed under the root.
   - Test: Task 1, `VocabularyTest.LevelsUpBeyondDepthFilesUnderRoot`.

- Modify: root `CMakeLists.txt` (`add_subdirectory(tools/convert_vocabulary)`)

**Interfaces:**
- **Consumes:** Task 1 `FromTree`.
- **Produces:**
  - `LoadText`, `LoadBinary`, `SaveBinary` (spec §2);
  - the executable `convert_vocabulary <in.txt> <out.bin>`, exit code 0 on success.
- **Text format:**
  - The header is `k L scoring weighting`. DBoW2 enum values: scoring `L1_NORM` = 0, weighting `TF_IDF` = 0. Check ORB-SLAM3's `TemplatedVocabulary::loadFromTextFile` for the exact enum numbering and follow it.
  - Node lines follow from id 1: `parent is_leaf d0 … d{B-1} weight`.
- **Validation (Review Focus 3, 4):**
  - token count and parse errors;
  - `parent < id`;
  - `is_leaf` agrees with whether the node has children;
  - descriptor bytes equal `FE::DescriptorSize`.
- **Binary format:** exactly as in spec §2, with FNV-1a 64 over all preceding bytes.
